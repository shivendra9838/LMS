# Employee Management Module Documentation

## 1. Employee Lifecycle
The Employee lifecycle within the LMS revolves around a strict enterprise rule: **Employees are never deleted**.
1. **Onboarding**: Employees are exclusively created by an Administrator. There is no public registration API.
2. **Active State**: Once created, an Employee is set to `ACTIVE` by default and given an auto-generated Employee Code (e.g., `EMP0001`).
3. **Offboarding**: If an Employee leaves the organization, they are not deleted from the database. Instead, an Admin patches their status to `INACTIVE`.
4. **Access**: An `INACTIVE` employee is blocked from logging into the platform at the authentication layer.

## 2. API List
All Employee APIs require a valid JWT token and an `ADMIN` role.

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/employees` | Create a new employee |
| `GET` | `/api/employees` | List all employees (supports pagination, search, sort) |
| `GET` | `/api/employees/:id` | Fetch full details of a specific employee |
| `PUT` | `/api/employees/:id` | Update an employee (Phone, City, Area) |
| `PATCH` | `/api/employees/:id/status` | Toggle employee status (`ACTIVE` or `INACTIVE`) |
| `GET` | `/api/employees/profile` | (EMPLOYEE ONLY) Fetch logged-in employee profile |

## 3. Validation Rules
- **Name**: Required string.
- **Email**: Required, valid format, must be **UNIQUE** across the system. Immutable after creation.
- **Phone**: Required, must be **UNIQUE** across the system.
- **City & Area**: Required strings.
- **Employee Code**: Auto-generated by the system (e.g., `EMP0042`). Cannot be manually assigned or updated.
- **Password**: Auto-generated securely during creation and hashed via `bcryptjs`. Never returned in API responses.

## 4. Status Flow
- **ACTIVE**: Employee has full access to their dashboard and capabilities.
- **INACTIVE**: Employee account is dormant. 
  - If an INACTIVE employee attempts to call `POST /api/auth/login`, the system intercepts the request and responds with a `403` status and `{ "message": "Employee account is inactive" }`.

## 5. Search, Pagination & Sorting
The `GET /api/employees` endpoint utilizes MongoDB queries to provide flexible data retrieval:
- **Pagination**: Use `?page=1&limit=10`. The response includes a `meta` object containing `total`, `page`, and `totalPages`.
- **Search**: Use `?search=xyz`. Performs a case-insensitive regex search across `name`, `email`, `phone`, and `employeeCode`.
- **Sorting**: Use `?sort=name` (ascending) or `?sort=-name` (descending). Defaults to newest first (`-createdAt`).

## 6. Standard Error Responses
The module adheres to a predictable error structure:
- **400 Bad Request**: Validation failures (e.g., `"Email already exists"`, `"Phone already exists"`, `"Invalid status"`).
- **401 Unauthorized**: Missing or invalid JWT token.
- **403 Forbidden**: Token valid, but user lacks `ADMIN` role, or attempting to login to an `INACTIVE` account.
- **404 Not Found**: Malformed Mongo ID (`CastError`) or employee does not exist.
- **500 Internal Server Error**: Unhandled exceptions.

## 7. Test Cases (Verified)
The following automated testing scenarios have been implemented and verified via `test-backend.js` and Postman:

### Create Employee
- ✅ **Valid Data**: Successfully creates and returns 201.
- ✅ **Duplicate Email**: Rejected with 400.
- ✅ **Duplicate Phone**: Rejected with 400.
- ✅ **Missing Required Fields**: Catches missing keys (e.g., Name) with 400.

### Update
- ✅ **Valid Update**: Successfully updates city/area and returns 200.
- ✅ **Invalid ID**: Returns 404 for random strings or non-existent IDs.
- ✅ **Invalid Status**: Returns 400 if patching status to anything other than `ACTIVE` or `INACTIVE`.

### List
- ✅ **Pagination**: Correctly limits payload length and calculates `totalPages`.
- ✅ **Search**: Accurately filters database records by partial string matches.
- ✅ **Sort**: Modifies ordering dynamically based on query params.
- ✅ **Empty Result**: Returns a 200 with an empty array `[]` rather than an error if search yields nothing.

### Authentication
- ✅ **Only Admin can Create**: Successfully blocks `EMPLOYEE` tokens from hitting the `POST` route.
- ✅ **Inactive Employee Login Blocked**: Successfully intercepts and rejects login attempts from deactivated accounts.
