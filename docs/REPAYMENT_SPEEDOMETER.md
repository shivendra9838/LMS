# Animated customer repayment speedometer

The existing shared CustomerRisk modal now includes a lazy-loaded semicircular repayment gauge, an accessible numeric readout, five visual bands, Lucide badges and metric icons, explanations, improvement guidance and the existing collapsible technical policy details.

## Compatibility and integration

Existing `react-gauge-component` 2.0.29 (MIT) is retained; no dependency change was needed for this fix. Its npm peer dependencies explicitly include React/ReactDOM 19, matching this project's React 19.2.8. References: [npm package](https://www.npmjs.com/package/react-gauge-component), [upstream API](https://github.com/antoniolago/react-gauge-component/blob/main/API.md).

`RepaymentSpeedometer.jsx` is shared by the existing risk modal. Existing customer lists/details, risk directory, loan detail and new-loan review placements therefore receive the same component. No duplicate API or scoring engine was introduced. Existing `/customer-risk/batch` and `/customer-risk/:id` fetches, notification refresh and 15-second refresh remain in use. A score change updates the mounted animated gauge; there is no hardcoded production score or editable score control.

Visual bands are 0–29 Very Bad, 30–49 Bad, 50–79 Average / Review Required, 80–89 Good and 90–100 Excellent. The original backend categories, weights, guardrails, evidence rules and thresholds (50/80) remain unchanged. The policy category is shown separately and remains authoritative.

## Needle rendering fix

Inspection of the installed library showed that its two-pass redraw/resize lifecycle can clear the D3-owned pointer. The earlier zero-duration workaround did not reliably preserve it. The existing RepaymentSpeedometer component now keeps the library for colored arcs and markings, with its internal pointer disabled. A separate gold/white SVG needle and circular pivot sit above that canvas. Their geometry comes from the rendered chart's coordinate system, so the needle stays centered after resize and never depends on D3 recreating it. This is one gauge in the existing component, not a duplicate component.

The needle uses a cancellable 1,500ms cubic easing animation, bounded to 0–180 degrees. A real score update starts from the last drawn position rather than zero. Opening a newly mounted modal starts at zero. Reduced motion snaps directly to the target. Resize changes geometry without resetting the current value. Geometry observers, animation frames and demo delays are canceled on unmount.

A Play-icon Test Speedometer button is available to authenticated Admin users in production and in development mode. It runs 0 → 25 → 50 → 75 → 100 → 0 once, clearly labels demo targets, keeps the actual customer rating visible, then restores the latest real score. Stop demo also restores the actual rating. Insufficient-history customers retain Not Rated Yet throughout. The demo contains no API, database or storage writes.

Insufficient History shows the full five-band arc with no needle or numeric score, a Clock3 badge and “Not Rated Yet.” Required due/completed counts come from the existing API policy (currently 5 due / 3 completed); current counts are displayed too. The invisible library coordinate of zero is never published as a customer score.

2. Confirm the modal's customer name and existing policy badge, numeric score and visual band. A new customer should display Not Rated Yet.
3. Check metrics, Why This Rating?, How to Improve? and the expandable policy section.
4. Open risk details from an existing loan or loan review location; the same gauge is used.
5. As Admin (or in local development), click Test Speedometer. Confirm the Demo Only label, sequence, unchanged customer score, and restoration afterward. Close the modal mid-demo and reopen; it must not resume the old demo.
6. On a phone, rotate the screen and enable the OS reduced-motion setting. Check that text stays readable and the needle is static and visible for rated customers.
