# Customer Management Module Documentation

## 1. Customer Lifecycle
The Customer lifecycle within the LMS revolves around a strict enterprise rule: **Customers are never deleted**.
1. **Onboarding**: Customers can be created by both `ADMIN` and `EMPLOYEE` roles. The system automatically tags the customer with the `employeeId` of the creator (or explicitly if assigned).
2. **Active State**: Once created, a Customer is set to `ACTIVE` by default and given a securely auto-generated Customer Code (e.g., `CUS000001`). This code is immutable.
3. **Offboarding**: If a Customer relationship ends, they are not deleted. Instead, an authorized user patches their status to `INACTIVE`.
4. **Loan Restrictions**: An `INACTIVE` customer cannot have new loans created under their profile.
5. **Timeline**: Every action (Creation, Loans, Payments) is immutably logged into a dedicated `CustomerTimeline` collection to track the customer journey.

## 2. API List
All Customer APIs require a valid JWT token and support both `ADMIN` and `EMPLOYEE` roles (with RBAC enforcement).

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/customers` | Create a new customer and log the initial timeline event |
| `GET` | `/api/customers` | List customers (Admins see all, Employees see only their own) |
| `GET` | `/api/customers/:id` | Fetch full details of a specific customer |
| `GET` | `/api/customers/:id/timeline` | Fetch the full audit timeline for a specific customer |
| `PUT` | `/api/customers/:id` | Update customer (Phone, City, Area, etc.) |
| `PATCH` | `/api/customers/:id/status` | Toggle customer status (`ACTIVE` or `INACTIVE`) |

## 3. Validation Rules
- **Name, Father's Name, Age, Occupation, Address, City, Area**: Required. Age must be >= 19.
- **Mobile**: Required, must be **UNIQUE** across the system. Validated for standard phone formats.
- **Customer Code**: Auto-generated by the system (e.g., `CUS000001`). Cannot be manually assigned or updated through the `PUT` endpoint.
- **Employee ID**: Handled natively by the backend via JWT decoding (`req.user.id`). Cannot be transferred or hijacked via `PUT`.

## 4. Status Flow
- **ACTIVE**: Customer is active and eligible for new loan generation.
- **INACTIVE**: Customer is dormant. Loan generation modules must reject requests against this status.

## 5. Search, Pagination & Filters
The `GET /api/customers` endpoint provides flexible data retrieval:
- **Pagination**: Use `?page=1&limit=10`. The response includes a `meta` object containing `total`, `page`, and `totalPages`.
- **Search**: Use `?search=xyz`. Performs a case-insensitive regex search across `name`, `customerCode`, and `mobile`.
- **Filters**: Supports `?city=Mumbai`, `?area=Vashi`, `?status=ACTIVE`. 
- **Admin Specific Filter**: Admins can use `?employee=EMP001` to filter all customers belonging to a specific loan officer.

## 6. Security & Role-Based Access Control (RBAC)
- **Employee Constraints**: Employees can only view, fetch details for, and update **their own** customers. If they attempt to fetch or update another employee's customer, the API returns a `404 Not Found` (rather than a 403 Forbidden) to disguise the existence of the ID for security.
- **Admin Unrestricted**: Admins can view, edit, and toggle the status of any customer in the system.
- **No Deletion**: There is no `DELETE` endpoint exposed to any role.

## 7. Test Cases (Verified)
The following scenarios have been structurally implemented and verified:

### Create Customer
- ✅ **Valid Data**: Successfully creates, auto-generates `customerCode`, links `employeeId`, logs timeline, and returns 201.
- ✅ **Duplicate Mobile**: Rejected with 400.
- ✅ **Missing Required Fields**: Catches missing keys (e.g., Name, Address) with 400.

### Update & Status
- ✅ **Valid Update**: Successfully updates allowed fields and returns 200.
- ✅ **Protected Fields Filtered**: Attempting to inject `customerCode` or `employeeId` in the `PUT` body is successfully ignored by the Service Layer.
- ✅ **Invalid Status**: Returns 400 if patching status to anything other than `ACTIVE` or `INACTIVE`.

### List & View
- ✅ **Admin Access**: Can list all customers globally.
- ✅ **Employee Isolation**: Employees strictly receive only their assigned customers in the list array.
- ✅ **Employee Unauthorized Access**: Directly calling `GET /api/customers/:foreign_id` with an employee token returns a disguised 404.
- ✅ **Timeline**: Successfully fetches timeline array sorted chronologically by default.
